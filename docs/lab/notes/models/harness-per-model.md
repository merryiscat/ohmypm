# 모델별 하네스 엔지니어링

2026-10-10 기준 · 문서 조사 · [추론 강도 문서](https://platform.claude.com/docs/en/build-with-claude/effort) · [GPT-5.6 지시문 안내](https://developers.openai.com/api/docs/guides/prompt-guidance-gpt-5p6) · Claude Code 2.1.295 도움말 직접 확인

## 핵심 요약
**요즘 모델은 '세게 말하기'보다 '설정을 맞추기'가 더 잘 듣는다. 모델마다 추론 강도 기본값이 달라서, 하네스가 강도를 직접 정하지 않으면 같은 일에 드는 비용과 품질이 모델마다 제멋대로 바뀐다.**

- **추론 강도(effort, 모델이 얼마나 생각하고 일할지 정하는 설정):** Opus 5.5와 Haiku 5.5의 기본은 medium, Fable 5.1과 Sonnet 5.5의 기본은 high다. 정해 주지 않으면 이 기본값을 따른다.
- **생각(thinking) 켜고 끄기:** Fable 5.1과 Opus 5.5는 생각을 끌 수 없다. 생각을 줄이려면 지시문을 바꾸지 말고 추론 강도를 낮춘다.
- **지시문 톤:** "절대", "반드시" 같은 강한 말을 여러 번 쓰면 요즘 모델은 지나치게 따르거나 몸을 사린다. Anthropic과 OpenAI 문서가 같은 말을 한다.
- **우리 쪽 판단(제안):** ohmyPM은 작업별로 모델은 정하지만 추론 강도는 정하지 않는다. 작업마다 강도를 함께 적는 것이 가장 효과가 클 것 같다.

## 하네스란
하네스는 모델을 감싸는 실행 틀이다. 지시문, 쓸 수 있는 도구, 권한, 문맥(모델에게 보여주는 자료) 관리, 결과를 검사하는 고리가 여기에 들어간다.

같은 모델이라도 하네스에 따라 결과가 크게 달라진다. 그리고 모델 세대가 바뀌면 예전 하네스가 오히려 방해가 될 수 있다. Anthropic은 "지시문은 모델마다 따로 맞춰야 하는 것이고, 한 세대에서 꼭 필요했던 문장이 다음 세대에서는 군더더기가 된다"고 적는다. 그래서 새 모델이 나올 때마다 지시문을 다시 점검하라고 권한다(Claude Code 내장 claude-api 안내서의 지시문 점검 절).

이 문서의 Anthropic 모델별 내용은 Claude Code에 함께 설치된 claude-api 안내서(모델 이전 안내, 지시문 점검 안내)와 위의 공식 문서를 근거로 한다.

## 모델 한눈에
값은 API 기준, 100만 토큰당 입력/출력 달러다.

- **Fable 5.1** — 10 / 50. 가장 강한 모델. 추론 강도 기본 high. 생각은 항상 켜짐.
- **Opus 5.5** — 4 / 20. 긴 코딩·지식 작업의 기본 선택지. 기본 medium. 생각은 항상 켜짐.
- **Sonnet 5.5** — 2 / 10. 기본 high. 생각을 아예 끄는 설정은 없고, 가장 낮은 설정(between_tools, 도구 호출 사이 짧은 메모만 남김)이 따로 있다.
- **Haiku 5.5** — 0.10 / 0.50(입력이 10만 토큰 이하일 때, 넘으면 0.50 / 2.50). 기본 medium. high 이하에서는 생각을 끌 수 있다.

네 모델 모두 다섯 단계(low, medium, high, xhigh, max)의 추론 강도를 받는다. 추론 강도는 생각의 양만이 아니라 도구 호출 횟수와 설명의 길이까지 바꾼다. 강도를 낮추면 도구 호출이 줄고 군말이 줄어든다. [출처](https://platform.claude.com/docs/en/build-with-claude/effort)

## Fable 5.1
가장 길고 어려운 작업에 맞춘 모델이다. 한 번의 요청이 15분씩 걸리는 것도 정상이라고 안내한다.

- **추론 강도:** high에서 시작하고, 일상 작업은 medium이나 low로 내린다. low에서도 이전 세대의 최고 강도보다 나은 경우가 많다고 한다. [출처](https://platform.claude.com/docs/en/build-with-claude/effort)
- **과잉 작업:** 강도가 높으면 시키지 않은 정리·리팩터링까지 한다. "요청한 범위만 하라"는 짧은 문장이 효과가 있다고 한다.
- **장황함:** 설명을 붙이지 않으면 결과물이 길어지는 경향이 있다. "결과부터 먼저 말하라"는 한 문장이면 충분하다고 한다.
- **진행 보고:** 이전 세대보다 중간 보고를 덜 한다. "중간 보고 하지 마라" 같은 옛 지시를 먼저 지우고, 그래도 부족하면 언제 보고를 원하는지 구체적으로 적는다.
- **진행 주장 검증:** 긴 작업에서 "끝났다"고 지어서 말할 수 있다. "보고하는 내용마다 이번 세션의 도구 결과로 근거를 대라"는 지시가 이를 거의 없앴다고 한다.
- **병렬 도구 호출:** 할 일이 명시되면 한꺼번에 부르지만, 암시만 되어 있으면 하나씩 부르기도 한다. 필요할 때만 "독립적인 것은 한 번에 요청하라"는 문장을 매 턴 끝에 덧붙인다.
- **조기 멈춤:** 긴 작업 끝에 "이제 X를 하겠다"고 말만 하고 멈추는 일이 드물게 있다. 무인 실행이면 "사용자가 지켜보고 있지 않다"는 문장을 지시문에 넣으라고 한다.
- **서브에이전트:** 이전처럼 위임을 막지 말고 자주 맡기라고 한다. 기다리지 않고 비동기로 맡기는 쪽이 더 빠르다.
- **거절:** 생물·사이버 분야 안전 필터가 있어 정상 요청도 가끔 거절된다. API에서는 대체 모델(fallback)을 처음부터 켜 두라고 권한다.

## Opus 5.5
Opus 5의 뒤를 이은 기본 Opus 모델이다. 값은 Opus 5보다 20% 싸고, 캐시 읽기는 입력가의 0.05배라 긴 대화에서 더 이득이다.

- **추론 강도:** 기본이 medium으로 내려갔다(Opus 5는 high). Anthropic 시험에서 Opus 5.5 medium이 Opus 5 high보다 코딩·지식 작업 점수가 높았다. xhigh·max는 측정으로 효과가 확인된 곳에만 쓴다. [출처](https://platform.claude.com/docs/en/build-with-claude/effort)
- **생각:** 끌 수 없다. "생각하지 마라"는 지시는 따를 수 없고 오히려 출력에 내부 태그가 새어 나오게 한다. 생각을 줄이려면 강도를 low로 내린다.
- **추론 노출 요구 금지:** 응답 본문에 "네 추론 과정을 그대로 적어라"라고 시키면 거절(reasoning_extraction)될 수 있다. 짧은 이유 설명을 요청하는 것은 괜찮다. [출처](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback#keep-reasoning-in-thinking-blocks)
- **도구 강제 금지:** 특정 도구를 반드시 쓰게 하는 API 설정은 오류가 난다. 지시문으로 유도하고, 실제로 불렀는지 코드가 확인한다.
- **진행 보고:** 도구 사이의 메모가 생각 블록으로 돌아온다. 화면이 조용해 보이면 하네스가 그 블록을 받아 보여줘야 한다.
- **글쓰기:** 작업 보고가 이전보다 쉬운 말로 나온다고 한다. Opus 5용으로 넣은 장황함·과잉 검증 억제 지시는 다시 시험해 보고 필요 없으면 뺀다.
- **화면 디자인:** "AI스러운 느낌을 피하라" 같은 막연한 말은 안 통한다. 피할 스타일을 이름으로 하나씩 적어야 듣는다.

## Sonnet 5.5
Sonnet 5와 같은 값에 성능을 올린 중간 등급 모델이다. 가장 어려운 장기 작업은 Opus가 낫다고 안내한다.

- **추론 강도:** 기본 high지만 단계가 다시 맞춰졌다. 에이전트 코딩·여러 단계 도구 사용은 medium, 대화·분류·추출·검색은 low가 출발점이다. [출처](https://platform.claude.com/docs/en/build-with-claude/effort)
- **생각:** medium 이상에서는 인사에도 잠깐 생각한다. 이때 "생각을 줄여라"라는 지시는 거의 효과가 없다. 강도를 낮추는 것이 답이다.
- **도구를 덜 쓰는 경향:** 대화형 작업에서 연결된 도구 대신 자기 지식으로 답하는 일이 있다. "꼭 필요할 때만 도구를 써라" 같은 문장은 글자 그대로 따르므로 지운다.
- **검증 생략:** 주로 low에서, 코드 변경을 실제로 돌려 보지 않고 "끝났다"고 보고하는 일이 있다. low로 돌릴 때는 "실제 검사를 돌린 뒤 보고하라"는 문단을 넣으라고 한다.
- **사용자 말의 위치:** 도구 결과 안이나 바로 뒤에 붙은 사용자 문장을 공격(프롬프트 주입, 외부 글에 숨긴 지시)으로 의심할 수 있다. 사용자 말은 별도의 사용자 차례로 넣는다.
- **거절:** 다섯 가지 분류(사이버·생물·경쟁 모델 개발·추론 노출·일반 유해)로 거절한다. 정상 작업도 가끔 걸린다.

## Haiku 5.5
분류·추출·짧은 하위 작업용의 가장 싼 모델이다. Haiku 계열에서 처음으로 추론 강도를 받는다.

- **추론 강도:** 기본 medium. 대화·짧은 도구 작업·대량 단순 요청은 low, 지식 작업과 지시를 엄격히 지켜야 하는 일은 high. [출처](https://platform.claude.com/docs/en/build-with-claude/effort)
- **생각이 기본으로 켜짐:** 짧은 답에 맞춰 출력 한도를 작게 잡으면 생각이 한도를 다 써서 답이 비어 버린다. 한도를 넉넉히 두거나 강도를 낮춘다.
- **같은 글이 약 30% 더 많은 토큰:** Haiku 4.5보다 토큰 계산이 늘었다. 비용 추정을 다시 해야 한다.
- **xhigh에서 빈 답:** 여러 차례 대화에서 답을 생각 안에만 쓰고 끝내는 일이 있다. 빈 답을 검사해야 한다.
- **긴 지시문 + low = 조기 멈춤:** 긴 에이전트 지시문을 low로 돌리면 일을 다 하지 않고 넘기는 일이 있다. 짧은 지시문에서는 드물다.
- **JSON 출력과 도구를 함께 쓸 때:** 생각을 끄면 필요한 도구 호출을 건너뛸 수 있다. 이런 요청은 생각을 켜 둔다.
- **거절:** 안전 필터가 새로 생겼고, 서버 쪽 대체 모델 기능은 없다.

## OpenAI 비교
OpenAI의 GPT-5.6 계열(sol·terra·luna) 안내도 방향이 같다. [출처](https://developers.openai.com/api/docs/guides/prompt-guidance-gpt-5p6)

- **추론 강도:** medium을 균형 잡힌 출발점으로, low는 품질이 유지될 때만 쓴다. high·xhigh는 평가에서 의미 있는 이득이 보일 때만. 강도를 올리기 전에 지시문에 성공 기준이나 검증 고리가 빠졌는지 먼저 보라고 한다.
- **모델별 기본값:** sol·terra·luna 각각의 기본 강도는 그 문서에 없다. 확인 못 함.
- **장황함:** 5.6은 5.5보다 기본적으로 간결하다. 길이는 별도 설정(verbosity)으로 기본값을 정하고, 작업별 길이는 지시문에 적는다.
- **지시문 톤:** "ALWAYS, NEVER, must"는 안전 규칙 같은 진짜 불변 조건에만 쓰라고 한다. "먼저 물어봐라"를 반복하면 안전한 작업에서도 불필요하게 멈춘다고 한다.
- **자율성:** 모델이 적극적이므로 요청이 허락하는 범위를 정해 주라고 한다. 범위 안의 수정과 되돌릴 수 있는 검사는 묻지 않고 하게 두고, 외부 쓰기·삭제·범위 확대만 확인받는다.
- **진행 보고:** 첫 도구 호출 전에 한두 문장, 이후에는 큰 단계가 바뀔 때만. 일상적인 도구 호출을 중계하게 하지 말라고 한다.
- **지시문 줄이기 효과:** OpenAI 내부 코딩 에이전트 평가에서 군더더기를 덜어낸 지시문이 점수를 약 10~15% 올리고 토큰을 41~66% 줄였다고 한다(작업마다 다르다는 단서 포함).

Codex(OpenAI의 코딩 에이전트)는 공식 안내에서 medium을 대화형 코딩의 기본으로, high·xhigh를 가장 어려운 작업용으로 권한다. 저장소 규칙은 AGENTS.md(Claude Code의 CLAUDE.md와 같은 역할)에 적는다. [출처](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide) [출처](https://developers.openai.com/codex/learn/best-practices) 다만 찾은 공식 Codex 안내는 gpt-5.3-codex 시절 글이라, 현재 Codex 기본 모델과 기본 강도는 확인 못 함.

## 공통 원칙
모델과 상관없이 문서들이 공통으로 권하는 것들이다.

### 지시문
- **세게 말하지 말고 정확히 말한다.** 대문자·"절대"·"반드시"가 많으면 표시가 의미를 잃고, 불안한 지시문은 몸 사리는 답을 만든다. 진짜 제약 한두 개만 이유와 함께 쓴다(내장 안내서 지시문 점검 절, OpenAI 안내도 같은 말). [출처](https://developers.openai.com/api/docs/guides/prompt-guidance-gpt-5p6)
- **방법보다 목표를 적는다.** 판단이 필요한 일에 "1단계, 2단계" 대본을 주면 오히려 품질이 떨어진다. 순서가 정말 중요한 위험한 작업(삭제·인증 등)만 정확한 절차를 준다.
- **'생각해라/생각하지 마라'는 지시문이 아니라 설정이다.** 생각의 양은 추론 강도로 조절한다.
- **맥락은 군더더기가 아니다.** 누가 읽는지, 무엇에 쓰는지, 품질 기준과 그 이유는 모델이 알 수 없으니 남긴다. 줄일 것은 모델이 이미 하는 일을 다시 시키는 문장이다.

### 코드와 지시문 나누기
- **결정론 코드가 할 일:** 분류표 조회, 숫자 계산, 이름 대조, 형식 정리, 반복 순회. 입력만으로 답이 정해지는 단계는 코드로 돌린다.
- **모델이 할 일:** 애매한 나머지를 판단하고, 요약하고, 글을 쓰는 단계 하나.
- **지시문은 코드 밖 파일에.** 고칠 때 코드 배포 없이 바꿀 수 있고, 무엇이 바뀌었는지 기록이 남는다.

### 권한과 검증
- **권한은 허용 목록으로.** 되돌릴 수 없는 행동(삭제, 외부 발신)은 모델 판단에 맡기지 않고 하네스가 막는다. 이런 행동은 전용 도구로 빼야 하네스가 가로채고 확인할 수 있다(내장 안내서의 에이전트 설계 절).
- **출력은 코드가 검사한다.** JSON은 정해진 형식(구조화 출력)으로 받는 것이 정규식으로 뽑는 것보다 확실하다. "JSON만 출력하라, 다른 글자는 절대 금지" 같은 문장과 재시도 고리는 구조화 출력이 대신한다.
- **거절과 빈 답을 따로 처리한다.** 요즘 모델은 정상 요청도 가끔 거절한다. 응답을 읽기 전에 거절인지 먼저 확인한다.

### 문맥과 캐시
- **캐시(같은 앞부분을 다시 보낼 때 싸게 계산해 주는 기능)를 깨지 않게 배치한다.** 바뀌지 않는 지시문을 앞에, 날짜·이력처럼 매번 바뀌는 것을 뒤에 둔다. 중간에 시스템 지시문이나 도구 목록을 바꾸면 캐시가 깨진다.
- **추론 강도를 대화 중에 바꾸면 캐시가 깨진다.** 한 작업 안에서는 고정한다. [출처](https://platform.claude.com/docs/en/build-with-claude/effort)
- **남은 토큰 수를 모델에게 보여주지 않는다.** 남은 양을 보면 서둘러 마무리하거나 작업을 줄이는 경향이 있다.

### 모델 등급과 비용
- **비용은 '토큰당'이 아니라 '끝낸 작업당'으로 본다.** 비싼 모델을 낮은 강도로 쓰는 것이 싼 모델을 높은 강도로 쓰는 것보다 쌀 때가 있다.
- **순서:** 캐시 → 입력 줄이기 → 추론 강도 낮추기 → 마지막에 모델 등급 낮추기. 모델을 바꾸는 것이 가장 위험한 변경이다.
- **서브에이전트는 덩치 큰 하위 작업에.** 하위 작업이 무거운 중간 자료를 흡수하고 한 줄만 돌려준다. 다만 판단하는 쪽이 그 중간 자료를 봐야 하면 나누지 않는다.
- **대화 중간에 모델을 바꾸지 않는다.** 캐시가 처음부터 다시 쌓이고, 앞 모델의 생각을 다음 모델이 못 읽는다.

## 우리 쪽 적용
아래는 ohmyPM 코드를 읽고 낸 **제안이다. 결정이 아니다.** 사용자가 고르기 전에는 바꾸지 않는다.

### 지금 하네스의 모습
- 모든 모델 호출은 `claude -p`(Claude Code 비대화 실행)를 띄워서 한다(`src/cc/client.py`).
- 작업 이름마다 등급(light·standard·heavy)이 있고, 등급별 모델은 설정이 정한다(`src/cc/models.py`). 기본값은 haiku·sonnet·opus다.
- 권한은 작업 유형별 허용 목록과 항상 막는 목록으로 정한다(`src/cc/permissions.py`).
- 지시문은 `prompts/*.md`에 있다. 시스템 지시문은 `--append-system-prompt`로 붙는다.
- 응답 JSON은 정규식으로 첫 `{...}`를 뽑아 읽는다(`src/cc/common.py`).
- 호출마다 비용을 세션 단위(1세션 = 약 80달러)로 기록한다. 이 점은 문서가 권하는 "비용 회계부터"를 이미 하고 있다.

### 1. 작업마다 추론 강도도 정하기 (효과가 가장 클 것으로 봄)
**지금 상태:** 호출에 `--effort`를 넘기지 않는다. 그래서 강도는 모델 기본값이나 이 PC의 개인 설정을 따른다. 2026-09-28의 "모델을 안 정하니 개인 기본(Fable)으로 돌았다" 사고와 같은 종류의 빈틈이다.

**제안:** `TASK_TIER` 옆에 작업별 강도 표를 두고 항상 `--effort`를 명시한다. Claude Code 2.1.295 도움말에서 `--effort <low|medium|high|xhigh|max>` 옵션을 직접 확인했다. 출발점 예시는 이렇다.

- **light(haiku) 작업** — 게시판 반응·댓글·복기: low. 짧고 정형이다.
- **정형 추출** — `model_catalog_extract`, `weekly_pm`의 JSON: medium에서 시작해 low가 버티는지 본다.
- **대화·자기 폴더 읽고 답하기** — `room_chat`, `weekly_agent`(sonnet): medium. 문서는 Sonnet 5.5 기본값(high)보다 한 단계 낮은 쪽을 대화·에이전트 작업의 출발점으로 권한다.
- **종합 글쓰기** — `weekly_report`, `model_catalog_profile`(opus): medium. Opus 5.5 기본과 같지만, 명시해 두면 나중에 모델이 바뀌어도 흔들리지 않는다.

강도별로 몇 번 돌려 비교한 뒤 정한다. 세션 비용이 매 호출 로그에 남으니 비교 근거로 쓸 수 있다.

### 2. JSON 작업은 형식 검사 옵션으로 받기
**지금 상태:** 시스템 지시문이 "JSON 하나뿐, 그 외 텍스트는 절대 금지"를 반복하고, 코드는 정규식으로 첫 중괄호 덩어리를 뽑는다. 문서가 오래된 방식으로 꼽는 조합이다.

**제안:** Claude Code에 `--json-schema`(정해진 JSON 형식을 검사하는 옵션)가 있다(도움말에서 직접 확인). 게시판·주간 PM·주간보고·모델 카탈로그처럼 JSON을 받는 작업부터 형식을 넘기고, 지시문의 "절대 금지" 문장은 한 줄의 평범한 형식 설명으로 줄인다. 이 옵션이 비대화 실행의 결과 JSON 어디에 어떤 모양으로 담기는지는 확인 못 함 — 한 작업에 먼저 시험해 봐야 한다.

### 3. 지시문 톤과 낡은 사실 정리
- **강한 말 줄이기:** `board_system.md`·`*_system.md` 여럿이 "절대 금지", "금지"를 반복한다. 진짜 제약(파일 수정 금지, 자기 글 제외 등)은 이유와 함께 남기고, 형식 강조는 2번이 대신하게 한다.
- **낡은 경로:** `room_chat.md`가 대상 프로젝트의 `docs/status.md`·`docs/log.md`를 열어 보라고 한다. 상위 CLAUDE.md에 따르면 이 파일들은 2026-10-09 llmwiki 제거 때 각 프로젝트에서 걷어냈다(project_odin 제외). 지금은 `ohmypm/state.md`나 CLAUDE.md·docs 전반을 가리키는 편이 맞아 보인다.
- **"인사말 반복·과한 서론 생략"** 같은 장황함 억제 문장은 Opus 5.5·Fable 5.1에서는 다시 시험해 볼 후보다. 다만 사용자가 매우 중시하는 "쉬운 말 규칙"과 "이모지 금지"는 모델이 알 수 없는 맥락이므로 그대로 둔다.

### 4. 도구가 필요 없는 작업은 도구를 아예 끄기
**지금 상태:** `weekly_pm`과 `weekly_report`는 허용 목록을 빈 칸으로 넘긴다. 코드가 빈 목록일 때 `--allowedTools`를 붙이지 않으므로, Claude Code 기본 도구 중 허락 없이 쓰는 읽기 도구가 열려 있을 수 있다.

**제안:** 입력만으로 답하는 작업에는 `--tools ""`(모든 도구 끄기, 도움말에서 확인)를 넘긴다. 도구 설명이 지시문에서 빠져 입력이 줄고, 모델이 엉뚱하게 파일을 뒤지는 일도 막힌다.

### 5. 비용 상한과 실패 처리
- **호출당 상한:** `--max-budget-usd`(비대화 실행에서 쓸 비용 상한)가 있다. 야간 배치에 작업별 상한을 걸면 한 호출이 세션을 다 먹는 일을 막는다. 맥스 요금제 사용량에도 이 상한이 적용되는지는 확인 못 함.
- **대체 모델:** `--fallback-model`은 도움말 기준으로 '과부하·사용 불가'일 때의 대체다. 안전 필터 거절 때도 작동하는지는 확인 못 함.
- **거절 감지:** 비대화 실행 결과 JSON에서 거절이 어떻게 보이는지는 확인 못 함. 지금 코드는 결과가 비면 None으로 처리하므로 크게 깨지지는 않지만, 로그에서 '거절'과 '실패'를 구분할 수 있으면 원인 찾기가 쉬워진다.

### 6. 주간 점검 대화의 문맥 배치
`weekly_pm.md`는 바뀌지 않는 설명을 시스템 지시문에, 이번 주 사실·카드·대화 이력을 본문 뒤쪽에 둔다. 문서가 권하는 "고정된 것 앞, 바뀌는 것 뒤" 배치와 이미 맞다. 다만 PM이 매 차례 새 `claude -p`로 대화 전체를 다시 보내므로, 차례가 늘면 비용이 늘어난다. 지금 최대 3차례라 문제는 작다.

### 하지 말아야 할 것
- **`--bare`는 쓰지 않는다.** 도움말에 따르면 이 모드는 API 키로만 인증하고 로그인 정보(OAuth)를 읽지 않는다. 맥스 요금제로 돌리는 지금 구조에서는 맞지 않는다.
- **헤드리스에서 Fable 금지 규칙은 유지한다.** Fable은 Opus 5.5보다 토큰당 2.5배 비싸다. 다만 문서는 "Fable low가 하위 모델보다 작업당 비용이 비슷하면서 더 잘할 때가 있다"고 하므로, 특정 작업에서 비교해 볼 여지는 있다.

## 확인 못 한 것
- Claude Code가 `--effort`를 주지 않았을 때 모델별로 어떤 강도를 쓰는지. API 기본값과 같은지, 개인 설정이 덮어쓰는지 확인 못 함.
- `--json-schema` 결과가 비대화 실행의 JSON 출력 어디에 담기는지.
- 비대화 실행에서 안전 필터 거절이 어떻게 표시되는지, `--fallback-model`이 거절에도 작동하는지.
- `--max-budget-usd`가 맥스 요금제 사용량에도 적용되는지.
- GPT-5.6 sol·terra·luna 각각의 기본 추론 강도, 현재 Codex 기본 모델과 강도.
- 이 문서의 Anthropic 모델별 행동 설명은 Anthropic 시험 결과를 옮긴 것이다. ohmyPM 작업에서 같은 결과가 나오는지는 우리가 직접 재 봐야 한다.
