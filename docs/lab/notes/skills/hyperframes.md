# HyperFrames — HTML로 영상 만들기

2026-10-10 조사·직접 시험 2회 기준 · v0.8.143 · [저장소](https://github.com/heygen-com/hyperframes)

## 핵심 요약
**HTML로 화면을 만들고 MP4로 뽑는 도구. 시각 연출은 좋지만, 한국어 음성과 음악은 별도 준비가 필요하다.**

- **직접 확인:** 계정·API 키 없이 로컬에서 51초 소개 영상을 완성했다.
- **잘하는 것:** 글자 애니메이션, 차트, 장면 전환, SVG와 3D를 섞은 화면.
- **아쉬운 것:** 한국어 내레이션과 배경음악. 이번 시험에서는 음질이 약했다.
- **우리 쪽 판단:** 기본 설치는 하지 않는다. 영상이 필요한 프로젝트에서만 설치한다.

## 어떤 도구인가
HeyGen이 만든 오픈소스 영상 제작 도구다(Apache 2.0). HTML·CSS로 장면을 작성하고 미디어에 시작 시각과 재생 길이를 지정하면, 크롬이 프레임을 찍고 FFmpeg가 MP4로 묶는다.

- **준비물:** Node.js 22 이상, FFmpeg.
- **제작 방식:** `data-start`·`data-duration`으로 시간을 지정한다. GSAP·CSS·Lottie·Three.js 애니메이션을 되감기 가능한 방식으로 쓴다.
- **에이전트와의 궁합:** 영상을 코드처럼 수정하고 다시 렌더할 수 있다. 같은 입력으로 같은 결과를 재현하는 방식이다.
- **로컬 사용:** 기본 렌더에는 계정이나 API 키가 필요 없다. 음성·음악 수급은 별개다.

## 직접 시험한 결과
### 시험 1 · 스킬 없이 만든 8초 영상
한글 제목, 숫자 카운터, 진행 막대로 기본 동작을 확인했다.

- 1920×1080 · 30fps · 8초 · 279KB.
- 렌더 시간 26초. 계정·키 없이 완결했다.
- 렌더 전 검사가 한글 폰트의 `@font-face` 누락을 잡았다. `src: local("Malgun Gothic")`로 고쳐 통과했다.

### 시험 2 · 스킬 21개로 만든 51초 소개 영상
위 플레이어의 영상이다. 새 세션에 스킬 21개를 설치하고 “ohmyPM 소개, 넣을 수 있는 기능 전부, 질문 없이”를 요청했다. 입구 스킬이 `general-video` 제작 흐름을 골랐다.

- **결과:** 51초 · 1080p.
- **렌더:** 2분 12초, RTX 3060 Ti 기준.
- **전체 작업:** Opus 5.5로 약 22분.
- **기록된 비용:** API 환산 약 6.8달러, 당시 계산으로 1세션의 약 6분의 1.

### 구현된 화면과 소리
- 장면 파일 7개와 2단 중첩, 장면 전환 5종.
- 한글 음절별 글자 애니메이션, SVG 선 그리기, 단어별 강조 자막.
- 카탈로그 차트 블록 개조, Three.js 3D.
- 번들 효과음 13개. 음성이 나올 때 배경음의 해당 대역을 줄이는 믹싱.

### 끝까지 해결하지 못한 부분
- **한국어 내레이션:** 내장 음성 합성 Kokoro가 한국어를 지원하지 않아 Windows 기본 음성을 썼다. 결과는 기계음에 가까웠다.
- **배경음악:** 선택한 경로에서 HeyGen 로그인이나 전역 Python 설치가 필요했다. 대신 직접 합성한 단순한 음을 사용했다.

## 어디에 쓰면 좋은가
아래는 제안 단계이며, 실제 도입을 결정한 것은 아니다.

- 프로젝트나 제품을 짧게 소개하는 영상.
- 유튜브 프로젝트의 쇼츠·인트로.
- 큰 PR의 변경점을 화면으로 설명하는 영상.

**화면 연출을 먼저 만들고 음성·음악을 따로 준비할 수 있는 작업**에 맞는다. 설치 명령은 각 프로젝트의 `ohmypm/skills.md`를 참고한다.

## 수집한 스킬의 구성
조사 당시 공개 스킬은 21개였다. 하나의 입구에서 요청에 맞는 제작 흐름과 기능 스킬로 연결된다.

- 입구 `/hyperframes` 1개 — 무엇을 만들지 묻고(의도 인터뷰) 우선순위 표로 제작 흐름 하나를 고른다
- 제작 흐름 10개 — 결과물 종류별 작업 순서
- 기능 스킬 — 작성 규약(core), 애니메이션, 키프레임, 디자인 방향(creative), 미디어 수급(media-use), CLI, 오디오 믹싱, 블록 카탈로그, Figma

## 요청에 맞는 제작 흐름
입구가 자동으로 고르지만, 요청을 이렇게 쓰면 정확히 간다.
- 사이트·제품 홍보 → `product-launch-video` — "이 URL로 45초 제품 소개 영상"
- 개념·주제 설명 → `faceless-explainer` — "이 글을 60초 설명 영상으로"
- PR 변경 설명 → `pr-to-video` — "이 PR을 변경점 소개 영상으로"
- 10초 미만 모션그래픽 → `motion-graphics` — "숫자가 튀어나오는 6초 통계 컷"
- 기존 영상에 자막·그래픽 → `embedded-captions` / `talking-head-recut`
- 음악 박자에 맞춘 영상 → `music-to-video`
- 발표 자료(영상 아님) → `slideshow`
- 그 밖·여러 기능 섞기 → `general-video` — 아래 시험 영상이 여기로 갔다

## 바로 쓸 요청문
주제·길이·화면 크기·톤·장면·필요한 요소를 한 번에 주면 사전 질문을 줄일 수 있다.

**제작 요청 예시**
Using /hyperframes, ohmyPM을 소개하는 45초 1920×1080 영상. 톤은 다크. 장면은 문제 소개 → 프로젝트 관리 화면 → 핵심 기능 → 마무리. 차트와 한글 자막을 넣고 화면 문구는 한국어로 작성.

**질문 없이 실행할 때 덧붙일 조건**
질문하지 말고 위 내용을 BRIEF.md에 기록해 진행. HeyGen 로그인·클라우드 렌더 금지. 렌더 전 check 통과. 끝나면 REPORT.md에 결과와 해결하지 못한 부분을 기록.

## 제작과 검수 순서
- `npx hyperframes init <이름> --non-interactive` → 장면 HTML 작성
- `npx hyperframes check` — 오류 0까지(폰트 누락·글자 겹침·대비 부족을 렌더 전에 잡는다)
- `npx hyperframes snapshot` — 정지 화면으로 눈 확인
- `npx hyperframes render` → 결과 MP4에서 프레임 몇 장 뽑아 확인
- 미리보기는 `npx hyperframes preview`(브라우저, 실시간 반영)

## 사용 전에 알아둘 점
### 화면과 파일 경로
- 한글 폰트는 `@font-face` 필수
- 하위 장면 파일 안의 자산 경로는 루트 기준 `assets/...`(`../assets/` 아님 — 문서끼리 안내가 엇갈린다)
- 장면 안에 넣은 부품의 고정 길이는 check가 못 잡는다 — 스냅샷으로 확인
- `preview`를 켜면 프로젝트 HTML을 자동 재포맷한다
- 카탈로그 검색은 영어만

### 설치와 실행 환경
- 익명 사용 통계는 `HYPERFRAMES_NO_TELEMETRY=1`로 끄고, 피드백 보고(`feedback`)는 보내지 않는다
- `init`은 기본으로 스킬을 따로 설치하려 한다 — `HYPERFRAMES_SKIP_SKILLS=1`
- `~/.cache/hyperframes`에 약 350MB(크롬·폰트) 캐시가 생긴다

## 스킬 설계에서 배울 점
- 입구 스킬이 "첫 번째로 맞는 행만 적용"하는 상태표로 시작 지점을 정한다(기존 프로젝트 수정이면 인터뷰 생략, BRIEF.md 있으면 질문 없이 재개)
- 경로마다 작은 계약 파일을 두고 그 파일만 읽게 해 문맥을 아낀다
- 렌더 전 검사 고리를 스킬이 강제한다
- 프로젝트가 CLI 버전을 고정하고, 올릴 땐 검사 후 이전·새 버전을 밝히게 한다
