# Ponytail(게으른 시니어 개발자 스킬) 검증과 계속 쓸지

기준 2026-10-10 · 핵심 근거: [JetBrains 독립 재측정](https://blog.jetbrains.com/ai/2026/07/ponytail-skill-claude-tested/), [원본 저장소](https://github.com/DietrichGebert/ponytail)

## 핵심 요약

**우리 PC에 깔린 것은 훅 없는 옛 버전 스킬 파일뿐이라 거의 작동하지 않고, 사용자 범위(모든 프로젝트·모든 헤드리스 호출에 적용되는 범위)에 둘 이유가 약하다. 지우고, 쓸 만한 규칙 두세 줄만 코딩 프로젝트 CLAUDE.md로 옮기는 쪽을 제안한다.**

- 우리 설치본은 2026-08-09에 `npx skills`로 받은 **스킬 파일 두 개**다. 플러그인도 아니고 훅도 없다. 내용은 원본의 2026-07-10 상태(v4 계열)와 한 글자도 다르지 않다. 원본은 2026-10-08에 "Ponytail 5"로 새로 짜였다.
- 독립 재측정(JetBrains)에서는 코드가 약 15% 줄었다. 원작자 주장(54%)의 4분의 1~절반 수준이다. 품질 차이는 측정되지 않았다. 원래 간단한 작업에서는 변화가 거의 0이었다.
- 같은 재측정에서 "훅 없이 스킬 파일만 두면 10번 중 한 번도 스스로 켜지지 않았다". 우리 설치 형태가 바로 이 경우다.
- Claude Code 기본 시스템 프롬프트에 이미 "요청보다 더 만들지 말라", "한 번 쓸 코드에 추상화를 만들지 말라"가 들어 있다(비공식 사본 기준). 핵심 규칙이 상당 부분 겹친다.

## 무엇인가

- Dietrich Gebert가 만든 MIT 라이선스(무료로 고쳐 쓸 수 있는 공개 라이선스) 규칙 묶음이다. AI가 "가장 게으른 시니어 개발자"처럼 생각하게 만든다. 먼저 "이게 꼭 필요한가"를 묻고, 그다음 순서로 답을 찾는다: 이미 있는 코드 → 표준 라이브러리 → 플랫폼 기본 기능 → 이미 깔린 의존성(가져다 쓰는 남의 코드 묶음) → 한 줄 → 최소 코드. [출처](https://github.com/DietrichGebert/ponytail)
- 스킬은 두 개다. `ponytail`은 코드를 짤 때 쓰고 강도를 lite·full·ultra 세 단계로 고를 수 있다. `ponytail-review`는 "지울 수 있는 것"만 찾는 리뷰다. 버그·보안은 다루지 않는다고 스스로 밝힌다.
- Claude Code 설치 명령은 `/plugin marketplace add DietrichGebert/ponytail` 다음에 `/plugin install ponytail@ponytail`이다. 두 명령은 따로 보내야 하고, 훅이 돌아가려면 Node.js가 있어야 한다. [출처](https://cdn.jsdelivr.net/gh/DietrichGebert/ponytail@main/README.md)

## 우리 설치본

- 위치는 두 곳이고 내용은 같다: `~/.claude/skills/ponytail`, `~/.claude/skills/ponytail-review`, 그리고 `~/.agents/skills/` 아래 같은 이름의 폴더 두 개. 설치 시각은 2026-08-09 13:07(세계 표준시)이다.
- `~/.claude/plugins/installed_plugins.json`에는 ponytail이 없다. 훅이 남기는 표식 파일(`~/.claude/.ponytail-active`)과 상태줄 스크립트도 없다. `settings.json`에도 ponytail 관련 항목이 없다. 그러니 **질문에 적힌 "세션 시작 때 규칙을 주입하는 훅"은 우리 PC에서 돌고 있지 않다.**
- 버전: 로컬 `ponytail/SKILL.md`는 원본의 2026-07-10 커밋(b6c0448) 파일과 같다. 그 뒤 첫 변경이 10-08의 Ponytail 5다. 그래서 우리 것은 "v4 계열 마지막 상태"다. 정식 번호 태그는 붙어 있지 않다. [출처](https://github.com/DietrichGebert/ponytail/commits/main/skills/ponytail/SKILL.md)
- 우리 쪽 규칙과 맞지 않는 점:
  - 로컬 `ponytail-review/SKILL.md` 예시에 체크·엑스 이모지가 들어 있다. 이 예시를 본뜬 리뷰 출력에 이모지가 섞일 수 있어 이모지 금지 규칙과 충돌한다.
  - 옛 버전은 코드 주석에 `ponytail:`이라는 상표 표식을 남기라고 시킨다. v5에서는 `shortcut:`으로 바뀌었다. [출처](https://github.com/DietrichGebert/ponytail/commits/main/skills/ponytail/SKILL.md)

## 주입량(토큰)

토큰은 AI가 글을 세는 단위로, 영어는 대략 4글자가 1토큰이다. 아래는 그 비율로 어림한 **추정치**이고 실제로 재지는 않았다.

### 우리 설치본(스킬만 있는 경우)

- 매 세션 항상 실리는 것은 두 스킬의 설명문(description)뿐이다. 합쳐 약 1,100자, 약 250토큰이다. 헤드리스(화면 없이 명령으로 부르는 방식) 호출도 마찬가지다.
- 본문은 AI가 스킬을 직접 불러올 때만 들어간다. `ponytail`은 약 5,900자(약 1,400토큰), `ponytail-review`는 약 2,300자(약 550토큰)다.

### 원본 플러그인을 깔 경우(v5 기준)

- 훅 세 개가 등록된다. [출처](https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/claude-codex-hooks.json)
  - **SessionStart**: 새 세션, 이어하기, 대화 지우기, 압축 때마다 실행된다. 규칙 본문과 "코드베이스 지도"를 주입한다. 지도는 현재 폴더의 함수·클래스 이름 목록이고 기본 상한은 2,000자다. 합치면 약 3,300자 + 2,000자로, **약 1,300토큰/회**로 추정한다. [출처](https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/ponytail-activate.js) [출처](https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/ponytail-map.js)
  - **SubagentStart**: 서브에이전트(작업을 나눠 맡는 보조 AI)가 시작될 때마다 같은 규칙을 다시 넣는다. [출처](https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/ponytail-subagent.js)
  - **UserPromptSubmit**: 사용자가 메시지를 보낼 때마다 실행되지만, `/ponytail` 명령이 아니면 아무것도 주입하지 않는다. [출처](https://raw.githubusercontent.com/DietrichGebert/ponytail/main/hooks/ponytail-mode-tracker.js)
- 건드리는 파일:
  - `~/.claude/.ponytail-active`(표식 파일)를 쓴다.
  - `~/.claude/.ponytail-statusline-nudged`를 쓴다.
  - 상태줄 스크립트를 `~/.claude/`에 복사한다.
  - `settings.json`은 읽기만 한다. 다만 상태줄이 설정돼 있지 않으면 "사용자에게 상태줄 설정을 먼저 제안하라"는 문장을 AI에게 주입한다.
- 외부 통신·텔레메트리(사용 기록을 밖으로 보내는 기능): 확인한 훅 파일들에는 없다. 지도 생성 때 로컬에서 `git ls-files`만 실행한다.

## 효과 평가

### 원작자 측정(자체 측정)

- v5 README 수치: 코드 -53%, 시간 -41%, 비용 -26%, 토큰 -45%. 조건은 Opus 5.5, 작업 39개, 작업당 5회, 총 585세션이다. [출처](https://github.com/DietrichGebert/ponytail)
- 상세 보고서에 적힌 한계와 결과 [출처](https://raw.githubusercontent.com/DietrichGebert/ponytail/main/benchmarks/results/2026-10-07-agentic.md):
  - Bash(명령 실행 도구)를 모든 비교군에서 껐다.
  - "작성한 코드만 쟀지 디버깅 능력은 재지 않았다"고 밝힌다.
  - 숨은 정답 검사 통과는 86/90(스킬 없음), 86/90(v4), 87/90(v5)으로 사실상 같다.
  - 이미 짧은 작업(9줄, 11줄, 3줄짜리)은 세 군 모두 줄 수가 같았다.
  - 일부 작업에서는 오히려 비쌌다. 예: auth-token 작업 $0.117 대 $0.081.
- 옛 버전 README의 "54%"는 Haiku 4.5로 12개 작업을 4회씩 돌린 결과였다는 소개 기사가 있다. 버전이 바뀔 때마다 측정 조건도 바뀌었다. [출처](https://pasqualepillitteri.it/en/news/5720/ponytail-ai-skill-less-code)

### 독립 측정

- **JetBrains(Denis Shiryaev, 2026-07)**: claude-sonnet-5, 실제 과제 모음(SkillsBench) 80개, 251회 실행. [출처](https://blog.jetbrains.com/ai/2026/07/ponytail-skill-claude-tested/)
  - 코드 -15.4%. 통계적으로 확실하지 않다(p=0.088, 우연일 가능성을 완전히 배제하지 못하는 수준).
  - 비용 -10.3%. 46개 작업에서 싸졌고 34개에서는 비싸졌다.
  - 품질: 65개 동일, 9개 약간 나쁨, 6개 약간 좋음. 차이 없음.
  - 이미 간결한 작업에서는 변화가 0이었다. 큰 작업에서는 코드가 31% 줄었다.
  - **훅 없이 스킬만 깔면 10세션 중 0회 켜졌다.** "SKILL.md만 스킬 폴더에 복사하면 아마 아무 차이도 못 잴 것"이라고 적었다.
  - 규칙 준수: `ponytail:` 주석 규칙은 80회 중 1회만 지켜졌다.
  - 한계로 스스로 꼽은 점: 화면 쪽 과잉 구현 함정이 적은 과제 모음이다. 즉 Ponytail에 불리한 쪽의 측정일 수 있다.
- **Stackademic 비평 글**: 이미 깔끔하게 쓰는 에이전트라면 기대 효과는 거의 0이라고 본다. 또 젊은 저장소의 자체 채점 수치만 믿고 "항상 켜져 코드를 실행하는 플러그인"에 모든 세션의 권한을 맡기는 것을 우려한다. 원문은 접속이 막혀(403) 검색 요약으로만 확인했다. [출처](https://blog.stackademic.com/does-the-ponytail-skill-actually-improve-claude-code-or-just-cut-its-line-count-9e2f31a3b32a)
- **중간 평가**: 82/100점을 준 리뷰가 있다. 이점은 토큰 절감보다 "층을 하나 더 만들 때마다 이유를 대게 만드는 것"이라고 보고, 자기 저장소에서 직접 비교해 보라고 권한다. [출처](https://soymarketingultra.com/en/ponytail-claude-code-review/)

### 홍보와 독립 평가 구분

- 독립: JetBrains 재측정이 사실상 유일한 정량 측정이다. v5에 대한 독립 측정은 아직 찾지 못했다.

## 기본 프롬프트와 겹침

- Claude Code 기본 시스템 프롬프트의 코드 스타일 절에는 다음 문장들이 있다(2026-04 비공식 사본 기준). [출처](https://www.cnblogs.com/panax/p/19810427)
  - "Don't add features, refactor code, or make "improvements" beyond what was asked."(요청보다 더 만들거나 고치지 마라)
  - "Don't create helpers, utilities, or abstractions for one-time operations."(한 번 쓸 코드에 도우미 함수나 추상화를 만들지 마라)
  - "Don't add error handling, fallbacks, or validation for scenarios that can't happen."(일어날 수 없는 상황에 대비한 오류 처리를 넣지 마라)
- 겹치는 부분: Ponytail의 1단계("필요한가")와 "요청 없는 추상화 금지"는 이미 기본에 있다.
- 기본에 없어서 Ponytail이 더하는 부분:
  - 표준 라이브러리 → 플랫폼 기능 → 의존성 순서의 사다리
  - "새 의존성을 몇 줄 때문에 들이지 마라"
  - 위험한 로직에는 작은 검사 코드 하나를 남겨라
  - 답변을 짧게 쓰는 출력 형식
- ohmyPM은 `--append-system-prompt`로 지시를 **덧붙이는** 방식이다(`src/cc/client.py:169`). 그래서 기본 시스템 프롬프트가 그대로 살아 있고, 위 겹침이 우리 헤드리스 호출에도 그대로 해당한다.

## 열린 문제

전부 2026-10-05~09에 열린 이슈다. [출처](https://github.com/DietrichGebert/ponytail/issues)

- #1043: macOS에서 훅 출력이 잘린다.
- #1045: 스킬 파일에 서명(진짜 원본임을 확인하는 장치)을 붙이자는 제안이 아직 열려 있다.
- #1036: 사용자가 직접 돌려 볼 수 있는 측정 도구를 요청하는 이슈다. 아직 없다.
- 플러그인 형태의 문제들이다. 훅이 없는 우리 설치본과는 직접 관련이 없다.

## 우리 쪽 적용

이 절은 제안일 뿐 결정이 아니다.

- **사용자 범위에서 지우는 쪽을 권한다.** 이유는 세 가지다.
  - 훅이 없어 거의 켜지지 않는다.
  - 켜지지 않아도 설명문은 ohmyPM의 모든 헤드리스 호출(보고서·연구·회의실 등 대부분 코딩이 아닌 작업)에 실린다.
  - 핵심 규칙은 기본 프롬프트와 겹친다.
- 지울 대상은 `~/.claude/skills/ponytail`, `~/.claude/skills/ponytail-review`, `~/.agents/skills/` 아래 같은 이름 두 폴더, 그리고 `~/.agents/.skill-lock.json`의 두 항목이다. `npx skills`에 제거 명령이 있는지는 확인하지 못했다. 지우기 전에 폴더 안을 한 번 보고 지운다.
- **원본 플러그인은 설치하지 않는 쪽을 권한다.** 사용자 범위에 깔면 약 40개 프로젝트의 모든 세션과 서브에이전트에 훅이 돈다. 또 `~/.claude`에 파일을 쓰고, 상태줄 설정을 권하는 문장을 주입하고, 각 프로젝트의 코드 이름 목록을 문맥에 넣는다(#1071). "다른 프로젝트는 ohmypm/ 폴더와 표식 블록만 건드린다"는 우리 원칙과 결이 맞지 않는다.
- **아이디어만 가져온다.** 코딩 비중이 큰 프로젝트(예: project_odin, runmagotchi)의 CLAUDE.md에 다음 정도만 적는다: "새 의존성을 들이기 전에 표준 라이브러리·이미 깔린 것·플랫폼 기본 기능을 먼저 본다", "위험한 로직은 작은 검사 하나를 남긴다". ohmyPM 화면(`src/web/routers/pages.py`)에는 "HTML·CSS 기본 기능 먼저"가 이미 맞는 방향이다.
- **리뷰 용도**는 내장 `/simplify`로 대신한다. 꼭 `ponytail-review`를 남기고 싶다면 사용자 범위가 아니라 필요한 프로젝트의 `.claude/skills/`에 복사하고, 이모지 예시를 글자 표기로 바꾼 뒤 쓴다.
- **재검토 조건(제안)**: 다음 중 하나가 생기면 v5를 프로젝트 하나에 프로젝트 범위로만 깔아 비교한다.
  - v5에 대한 독립 측정이 나온다.
  - 이슈 #1036(사용자가 직접 돌리는 측정 도구)이 반영된다.
  
  재검토 날짜나 조건을 고정해 project_odin의 `docs/pending.md` 같은 문서에 적는 일은 사용자 확인이 필요하다.

## 확인 못 한 것

- 주입 토큰 수는 모두 글자 수로 어림한 값이다. 실제 토큰 계산은 하지 않았다. 코드베이스 지도 크기는 프로젝트마다 다르다.
- JetBrains가 시험한 정확한 Ponytail 버전은 확인하지 못했다. 7월 시점이라 v4 계열로 추정한다. v5에 대한 독립 측정은 찾지 못했다.
- Claude Code 기본 시스템 프롬프트 문구는 비공식 사본(2026-04)으로만 확인했다. 지금 버전(2.1.2xx)에서 문구가 바뀌었는지는 확인하지 못했다.
- 측정 방식이 서로 다르다. 원작자 측정은 Bash를 끄고 Opus 5.5를 썼고, JetBrains는 Sonnet 5를 쓰고 규칙을 작업 뒤에 붙였다. 그래서 두 수치를 바로 비교하기 어렵다.
- 별 수는 출처마다 크게 엇갈린다(1.9만~16만). 별 수가 부풀려졌는지는 확인하지 못했다.
- Stackademic 비평 원문은 접속이 막혀 직접 읽지 못했다.
- `ponytail-config.js`, `ponytail-runtime.js`는 직접 열어보지 않았다. 이 두 파일에 외부 통신이 없다는 것은 다른 훅 파일들로 미루어 본 것이다.
- 스킬을 지우는 정식 명령(`npx skills` 쪽)이 있는지 확인하지 못했다.
