# T-004 일간보고 중복·반복 질문·활동 오탐 제거
- 상태: 검토 반영 v2
- 등급: M (차선 M) — 발화 저장·PM 팩트·활동 판정과 최소 DB/스캔 연계에 설계 판단 필요.
- 작성: pl, 2026-09-18
## 목표
일간보고가 담당 대화를 가리고, 닫힌 권한 이슈를 되묻고, 손대지 않은 프로젝트까지 점검하는 잡음을 없앤다. 실제 활동 프로젝트를 점검하되 특정 프로젝트 이름으로 제한하지 않는다.
- 근거①(main 코드 확인): `src/cc/daily_report.py`가 PM·담당 발화를 `daily::날짜::경로`와 프로젝트 방(경로)에 이중 저장해 오른쪽 패널에 중복 표시한다.
- 근거②(main 코드 확인): `build_facts`의 기한·이슈 목록은 `verdict=drop`만 제외한다. 9/6 공개했다고 알린 구글 권한 이슈가 resolved인데도 9/15 기한으로 매일 재주입된다.
- 근거③(main 코드 확인): 9/17 파서 변경으로 제목·fingerprint가 바뀐 재생성 이슈를 24시간 내 활동으로 보아 9/18에 13개를 점검했다. 커밋 필터도 ohmyPM만 제외해 T-003의 23개 프로젝트 kickoff-workspaces 설치 커밋이 다음 날 활동으로 잡힐 예정이다.
## 범위
- 안: 일간 발화 단일 저장, 기존 중복의 조회 필터, 열린 이슈 팩트, 도구 커밋·도구 출처 이슈 제외, 스캔 신규 이슈의 원본 docs 파일 mtime으로 활동 판정.
- 밖: UI 개편, Google 권한 조작, 프로젝트 등록 변경, 이슈 상태·기한 수정, 기존 메시지 삭제·이동, 스키마 변경·마이그레이션, 스캔 회차·stale 시각 기록 및 판정.
## 완료 기준 (관찰 가능한 문장 — 기준 하나에 확인 방법 하나)
1. [ ] 새 일간 점검의 PM·담당 발화는 해당 일간 방에만 나타나고 프로젝트 방에는 추가되지 않으며, 사용자와 담당의 직접 대화는 종전대로 남는다 — 확인: 격리 DB에서 두 흐름 실행 후 방별 조회 비교.
2. [ ] 기존 프로젝트 방 발화 중 같은 프로젝트·일자(KST)·작성자·본문이 일간 방과 일치하는 PM·담당 발화만 조회에서 숨긴다(사용자 발화 제외); DB 원본과 일간 방 조회는 보존한다 — 확인: 일치/불일치/사용자 발화를 넣은 조회 재현으로 패널 공급 목록과 원본 비교.
3. [ ] `build_facts`의 기한·이슈 상세는 open·consulting·needs_user이면서 verdict≠drop인 행만 포함한다; resolved·deferred·stale은 제목·기한 없이 상태별 개수(완료/보류/지난 것)만 전달하고 drop은 집계에서도 제외한다 — 확인: 6개 상태와 drop, 위 구글 이슈를 포함한 입력의 팩트 출력 대조.
4. [ ] 최근 24시간 커밋 메시지에 대소문자 구분 없이 `ohmyPM` 또는 `kickoff-workspaces`가 포함되면 활동 신호에서 제외하고 나머지 커밋은 유지한다 — 확인: 두 도구 메시지·일반 메시지·24시간 밖 메시지의 활동 판정표 재현.
5. [ ] 이슈 활동은 최근 24시간 생성된 열린 스캔 이슈(verdict≠drop) 중 `source`가 가리키는 해당 프로젝트 docs 파일의 mtime도 판정 시각 기준 [현재−24시간, 현재]에 있을 때만 인정한다; `source='daily_report'` 등 도구 출처·원본 파일/mtime 확인 불가는 제외한다. 도구 커밋·도구 이슈·오래된 문서의 재생성만 있으면 일간 PM/담당 호출 0회, 일반 커밋 또는 위 조건의 신규 이슈가 있으면 점검한다 — 확인: 도구 출처, 오래된/최근 수정/없는 원본, 생성 시각·mtime의 24시간 경계, 일반 커밋 동반 여부를 조합한 격리 재현.
## 손대는 파일
- `src/cc/daily_report.py` 중심; 필요한 경우 `src/db/`의 메시지·활동 조회와 `src/scan/`의 기존 source 경로 연결만 최소 수정. 기존 source로 원본 docs 파일을 찾아 mtime을 읽으며 새 스키마·회차 기록·stale 시각 판정은 추가하지 않는다.
## 필요 도구
없음(신규 설치 금지). 워커는 기존 실행 환경과 격리 데이터로 기준을 재현하며 운영 배치·외부 발신은 실행하지 않는다.
