# 요청: ohmyPM '환경 세팅' 기능 — 구현 작업 지시서(프롬프트) 작성

받는 쪽: 아스트라(Codex). 작성 2026-10-11. 저장소: 이 ohmyPM 저장소(`C:\Users\minhy\project\ohmyPM`).

## 너의 일 (중요)

**코드를 짜지 않는다. 파일을 하나도 만들거나 고치지 않는다.** 실제 구현은 Claude(Claude Code)가 한다.
너는 저장소를 읽고, 아래 요구사항을 이 저장소 현실에 맞춰 구체화한 **Claude용 구현 작업 지시서 하나**를 답으로 내놓는다.
지시서는 Claude가 그대로 받아 바로 작업을 시작할 수 있어야 한다.

지시서에 반드시 들어갈 것:
1. 작업 순서 — 단계별로, 단계마다 만들거나 고칠 파일 경로(실제 저장소에 있는 이름으로)와 그 안에서 할 일
2. 재사용할 기존 함수·패턴의 정확한 위치(`파일:줄` 또는 함수 이름) — 새로 만들지 말고 가져다 쓸 것
3. 데이터 모양 — DB 표 열, 제안 JSON 형식, API 경로·요청·응답
4. 테스트 목록 — 테스트 이름과 각각 무엇을 확인하는지
5. 완료 조건 — Claude가 끝났다고 말하기 전에 확인할 것
6. 열린 질문 — 저장소만 읽어서는 정할 수 없어 사용자에게 물어야 하는 것(있으면). 추측으로 메우지 말 것

지시서는 한국어로, 이모지·장식 기호 없이, 설명 없는 줄임말 없이 쓴다.
아래 1~6절은 지시서가 담아야 할 요구사항이다.

## 0. 먼저 읽을 것

지시서를 쓰기 전에 아래를 읽고, 기존 방식에 맞춘 지시를 써라. 새 구조나 새 라이브러리를 들이는 지시는 하지 않는다.

- `AGENTS.md`, `CLAUDE.md` — 작업 규칙(모델 호출, 지시문 위치, 다른 프로젝트 파일 규칙과 그 예외)
- `docs/design.md`(특히 4절 경계 표의 '환경 세팅(계획)' 줄), `docs/interfaces.md`
- `kit/README.md` — 환경 세팅 재료와 검증 상태. `docs/references.md` — 외부 도구 판정 기록
- 비슷한 흐름의 기존 코드: `src/cc/weekly_report.py`(수집은 코드 → 모델 1콜 JSON → 코드가 나눠 저장),
  `src/install.py`(다른 프로젝트 파일을 원문 그대로 읽고 쓰기 — `_read`/`_write`, CRLF 보존, `@AGENTS.md` 처리),
  `src/cc/client.py`의 `run_headless_ex`, `src/cc/models.py`, `src/cc/permissions.py`, `src/jobs.py`,
  `src/web/routers/api.py`, `src/web/routers/pages.py`(화면 전부가 Python 문자열 `_HTML` 안의 단일 HTML)
- `tests/test_weekly.py`, `tests/test_install*`(있으면) — 테스트 작성 방식

## 1. 배경과 목적

ohmyPM은 이 PC의 로컬 프로젝트 약 27개를 관리한다. 지금 각 프로젝트에 넣는 `ohmypm/` 폴더와 CLAUDE.md·AGENTS.md
표식 블록은 **주간보고용**이다. 이와 별개로, 프로젝트의 **처음 환경 세팅**을 ohmyPM이 해 주려 한다:
CLAUDE.md·AGENTS.md를 손보고, 쓸 만한 스킬을 제시하고, 하네스(에이전트가 일하는 환경: 지침 문서·권한·문서 구조)를 잡아 준다.

가장 중요한 교훈: 예전 kickoff_pack은 **검증되지 않은 하네스 엔지니어링을 하다 보니 프로젝트가 더 고장 났다.**
그래서 이 기능은 "많이 깔아 주기"가 아니라 "검증된 것만, 보여 주고, 승인받은 것만, 되돌릴 수 있게"다.

## 2. 1차 범위

### 2-1. 수집 (코드만, 모델 호출 없음)
프로젝트 한 개의 스냅샷을 만든다.
- 언어·패키지 관리 도구 단서: `pyproject.toml`, `uv.lock`, `requirements.txt`, `package.json`, `pnpm-lock.yaml` 등 유무
- 화면 유무: html·css·js·jsx·tsx·vue·svelte 파일 수(`node_modules`·`.venv`·`.git` 제외)
- 테스트 폴더·테스트 명령 단서, `docs/` 파일 목록
- 기존 `CLAUDE.md`·`AGENTS.md` 전문(길면 앞부분만, 상한을 상수로), `@AGENTS.md` 불러오기 여부
- `.claude/settings.json`·`.claude/settings.local.json`의 권한·훅 요약, `.claude/skills/` 목록
- `.gitignore`가 `.env`를 빼는지
- `ohmypm/` 표식 블록 위치(이 블록은 `src/install.py` 소관이라 건드리지 않는다)

### 2-2. 제안 (모델 1콜, JSON)
수집 결과 + `kit/README.md` 재료 표를 넣고 제안서를 받는다. 항목 하나 = 바꿀 것 하나.
- 형식 예: `{"items": [{"id", "kind": "claude_md|agents_md|settings|skill|doc", "title", "why", "target": "상대경로",
  "op": "create|append|replace", "before": "바꾸기 전 원문 조각(replace일 때)", "after": "바꾼 뒤 내용", "material": "kit 재료 이름 또는 null"}]}`
- 항목 수 상한(예: 8개). 한 번에 크게 바꾸지 않는다.
- 1차에서 제안할 수 있는 것:
  - CLAUDE.md: 응답 언어, 실행·검증 명령(실제 파일에서 확인된 것만), 문서 목차. 이미 있는 내용과 겹치거나 어긋나는 줄 정리
  - AGENTS.md: CLAUDE.md와 어긋나지 않게(한쪽이 다른 쪽을 불러오는 구조면 그 구조를 유지)
  - `.claude/settings.json`의 권한 거부 규칙(예: `.env` 읽기·`rm`·강제 푸시 막기) — Claude Code 기본 기능만
  - 스킬: `kit/` 재료나 `docs/references.md`에서 채택된 것 **제시만**. 설치 명령을 보여 주되 실행하지 않는다
- 제안하지 않는 것: 훅 추가, 역할별 에이전트·폴더 트리 같은 큰 구조, 외부 서비스 연결, `kit/README.md`에 없는 재료
- `kit/README.md`에서 상태가 "시험 전"인 재료는 제안에 넣되 `experimental: true`로 표시하고 화면에서 따로 구분한다
- 모든 `after`·`why`는 한국어, 이모지·장식 기호 금지, 설명 없는 줄임말 금지

### 2-3. 화면
- 프로젝트 화면(`pages.py`의 경로·설치 버튼이 있는 `kv` 영역 근처)에 "환경 세팅" 버튼
- 누르면 백그라운드 작업으로 수집·제안(`src/jobs.py`). 끝나면 항목 목록:
  항목마다 제목·이유·대상 파일, 바꾸기 전/후 비교, 승인 체크박스. 실험 재료는 눈에 띄게 구분
- "승인한 것 적용" 버튼, 적용 결과(성공·실패·건너뜀), 적용한 실행 단위로 "되돌리기" 버튼
- 기존 화면 규칙을 지킨다: 이모지 금지, 글자 대비 4.5:1, 포커스 표시, 오류 안내는 `errMsg`, 목록 갱신은 `setHTML`

### 2-4. 적용 (코드만)
- 승인된 항목만 쓴다. 쓰기 전에 원본을 `<프로젝트>/ohmypm/setup-backup/<시각>/`에 그대로 복사한다(`ohmypm/`는 git에서 빠진다)
- 제안 시점의 대상 파일 해시를 기억했다가, 적용 직전과 다르면 그 항목은 쓰지 않고 "파일이 바뀌어 건너뜀"으로 남긴다
- `replace`는 `before` 조각이 파일에 정확히 한 번 있을 때만. 아니면 건너뜀
- 원문 그대로 읽고 쓴다(`install.py`의 `_read`/`_write`처럼 `newline=""` — CRLF를 바꾸지 않는다)
- 표식 블록(`<!-- ohmypm:start -->`~`end`) 안은 절대 건드리지 않는다
- 되돌리기: 백업에서 그 실행이 바꾼 파일만 되살린다(새로 만든 파일은 지운다)
- 커밋하지 않는다. 스킬·플러그인 설치 명령을 실행하지 않는다. `~/.claude` 등 사용자 범위는 읽지도 쓰지도 않는다
- ohmyPM 자기 자신(`is_self_project`)은 대상에서 뺀다

### 2-5. 기록
- DB(`src/db/schema.sql`에 표 추가, 기존 DB는 `_migrate` 방식): 실행 단위(프로젝트, 시각, 상태, 비용)와 항목 단위
  (제안 내용, 상태 proposed/approved/applied/skipped/rejected/reverted, 건너뛴 이유)
- API는 `api.py`에 기존 이름 규칙대로. 라우트에서 모델을 직접 부르지 않는다

## 3. 지켜야 할 기존 규칙

- 모델 호출은 `run_headless_ex(task="env_setup")`. `src/cc/models.py`의 `TASK_TIER`·`TASK_EFFORT`에 먼저 등록(종합 판단이라 heavy·high 권장)
- 권한은 `src/cc/permissions.py`의 읽기 전용 기본(Read·Grep·Glob), `cwd=neutral_cwd()`, `add_dirs=[프로젝트 경로]`
- 지시문은 코드가 아니라 `prompts/env_setup.md`(`${변수}`)와 `prompts/env_setup_system.md`
- 주석은 비개발자도 읽을 수 있게 쉽고 넉넉히, 한국어. 커밋 메시지도 한국어
- 비용 이야기는 달러가 아니라 세션 단위(1세션 = `settings.session_usd` 달러어치) — 화면은 기존 `fmtCost` 사용
- 사용자는 Windows 11 + PowerShell. 경로와 인코딩(UTF-8)에 주의

## 4. 확인

- `uv run pytest` 전부 통과 + 새 테스트:
  수집 스냅샷, 제안 JSON 파싱(깨진 JSON 처리 포함), 승인 안 된 항목은 파일 불변, 해시가 바뀐 파일 건너뜀,
  `replace`의 `before`가 없거나 여러 번이면 건너뜀, CRLF 보존, 표식 블록 불변, 되돌리기 후 원상복구, 자기 자신 제외
- 서버 재기동: `scripts\stop_ohmypm.cmd` → `.venv\Scripts\pythonw.exe scripts\run_ohmypm_hidden.py`, 화면에서 버튼·목록·적용·되돌리기 확인
- 실제 프로젝트에는 **제안까지만** 돌려 본다. 적용은 사용자가 화면에서 직접 승인할 때만 한다
- 문서 갱신: `docs/design.md` 경계 표의 '환경 세팅(계획)'을 실제 동작으로, `docs/interfaces.md`에 API, 필요하면 `kit/README.md`
