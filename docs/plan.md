# ohmyPM 기획 (킥오프 1부 초안)

derived_from: 대화 2026-08-20 (킥오프 1부 인터뷰)

## 1부 요약

ohmyPM은 사용자의 모든 로컬 프로젝트를 매일 돌보는 **메타 PM 에이전트**다. 킥오프팩을
만들면서 확인한 문제 — 하네스 엔지니어링과 프로젝트 환경 관리가 부실하면 모델 품질이 확
떨어진다 — 를 해결하기 위해, 프로젝트 매니저가 할 일을 에이전트가 매일 대신 수행한다.
형태는 **Claude Code 기반 에이전트**(스킬 + 스케줄, 별도 앱·화면 없음)이고, MVP 범위는
① 환경·하네스 점검(CLAUDE.md·스킬·훅·설정의 부패/노후 감지·업데이트), ② 진행 상황
추적 + 데일리 브리핑(오늘 할 일 제안·우선순위·일정 제시), ③ 문서·위키 건강 관리(llmwiki
lint 연계), ④ 자율 업무 실행(사용자 판단이 필요 없는 업무는 직접 처리)이다. 보고 채널은
**텔레그램 알림**. 산출물은 코드/하네스(스킬·스케줄 구성)다.

## 핵심 골자 — 기반·진화·뼈대 (derived_from: 대화 2026-08-22)

세 층으로 본다:
- **킥오프팩** = 프로젝트의 **기반을 올바르게 잡는다** (기초 결정·스택·하네스를 초기에 바로 세움)
- **ohmyPM** = 그 기반 위에서 **올바르게 세워나가며 변화하는 환경에 대응한다** (매일 돌보기)
- **위키(llmwiki)** = 그 둘을 잇는 **연속성의 뼈대** — 기반의 결정·전제를 살아있게 이어가고, 환경이 바뀌어 전제가 낡으면 그걸 들춰낸다

함의(2026-08-22 근본 검토 결론): 위키가 PM을 개선하는 지점은 **능동적·강제적 장치**(때 되면 안건을 밀어올리는 재부상 훅, 항체를 만들게 강제하는 규칙, 흡수된 걸 지우는 다이어트)이지 **수동 보관함**(검색·index·페이지 택소노미·raw 축적)이 아니다. 틀린 위키는 없는 위키보다 나쁘다(신뢰되므로). 그래서 위키 개선의 방향은 검색을 붙이는 게 아니라 **강제 장치 강화 + 보관함 ceremony 감축**이다. 규모·리스크가 큰 프로젝트일수록(예: naverblog 자율 운영) 밥값이 크고, 작고 미완인 프로젝트(현재 ohmyPM 자신)에선 관리 비용이 이득을 넘볼 수 있다.
