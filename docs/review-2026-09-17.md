## 2. 설계 — 목적에 맞는 것과 어긋난 것

**남길 설계**: 수집=결정론/판단=LLM 분리 · 화이트리스트 3중 방어(permission-mode·allowedTools·PreToolUse 훅) · 되돌리기 불가 행동 원천 제외 · 변화 없는 프로젝트 콜 0회 게이트 · 지시문 탈코드화(prompts/) · 실수 연대기→항체 체계와 confused-deputy 인식.

**어긋난 설계**:
1. **알림 채널 미검증** — 텔레그램 발송 함수가 성공을 로그에 안 남겨, 2주치 로그에 발송 흔적이 "요약 없음" 한 줄뿐. 실제로는 대시보드를 열어야 보임 = "봐야 안 놓친다".
2. **핵심 케이스 4(상시 감지·소견 상담)·8(기한 재부상)이 비어 있음** — heartbeat는 빈 껍데기라 제거(09-09), 재부상은 칸반 날짜 표시까지만.
3. **게시판 생태계는 성공 기준 어디에도 없는데 하룻밤 모델 호출의 대부분** — 글 24·둘러보기 24·반응·대대댓글·조언 반영 14·기록 정리 25·총괄 2.
4. **감시자가 가장 활발한 기여자** — 담당이 매일 밤 남의 프로젝트 docs를 고치고 코드가 커밋. 손 덜 대는 프로젝트일수록 기록의 다수를 에이전트가 씀. plan.md의 "틀린 위키는 없는 위키보다 나쁘다"와 매일 25배로 충돌. 화이트리스트(사용자 등록만 자율) 원칙과 긴장.
5. **진실이 두 곳** — 이슈 원천은 docs, 칸반 상태는 SQLite. 담당은 docs를, PM은 DB를 고침. 09-14 대화에서 "담당 37건 vs 총괄 38건, 담당은 칸반을 볼 수 없다"가 실물.
6. **자기 자신에게는 '실패를 시끄럽게' 원칙이 없음** — 단일 프로세스, 사람이 재시작을 기억, 서버가 죽으면 아무도 모름. 첫 잡이 죽으면 뒤 잡 전부 죽음.
7. **테스트 0건, 비용 계측 0건** — headless 응답 JSON의 total_cost_usd를 버림(실패 로그에서만 한 호출 0.36달러가 스침).
8. **argv 재파싱 함정 3변종** — subprocess로 claude.CMD를 부르는 구조의 취약점. 근본 차단 보류 중. Python Agent SDK로의 통로 교체는 재검토 시점.
