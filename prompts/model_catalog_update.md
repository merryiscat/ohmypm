가져온 문서 중 이전 반영본과 비교했을 때 새로 생기거나 바뀐 절이다. ${window_note}

[달라진 부분 원문]
${diff_text}

위 원문만 근거로, **모델에 관한 변경 사실**을 JSON 배열로만 출력하라(설명·인사·코드펜스 없이 배열 그 자체).

모델에 관한 것만 담는다 — 새 모델 출시·모델 은퇴/폐기·특정 모델의 능력·동작·가격·컨텍스트·추론 설정 변화,
그리고 특정 모델(또는 모델 라인업 전체)에 대한 사용법·프롬프트·추론 설정·컨텍스트 관리·도구 사용 안내.
**모델과 무관한 플랫폼·API·SDK·콘솔·앱 기능 변경(예: Files API, 인용 기능, SDK 릴리스, 앱 버전, 대시보드 UI)은 담지 않는다.**
그런 것만 있으면 빈 배열 []을 출력한다.

각 항목은 다음 필드를 모두 갖는다:

{
  "name": "변경 제목(짧게)",
  "model": "이 변경이 속한 모델의 정식 이름 하나(예: Claude Opus 5.5, GPT-6 Sol). 라인업 전체에 걸친 정책이면 '라인업 공통'",
  "announced_date": "YYYY-MM-DD 또는 원문에 없으면 null",
  "confirmed_date": "오늘 날짜(YYYY-MM-DD)",
  "diff": "이전과 달라진 점 — 원문 근거만, 구체적으로(수치·ID·설정 이름 포함). 없는 사실을 더하지 않는다",
  "usage_tips": ["이 모델을 잘 쓰기 위한 팁 — 원문이 말한 것만. 없으면 빈 배열"],
  "harness_changes": ["하네스(프롬프트·추론 설정·컨텍스트 관리·도구 사용·설정 파일)에서 바꿔야 할 것 — 원문이 말한 것은 그대로, 우리 판단이면 문장 앞에 '(제안)'"],
  "impact_type": "asserted(원문이 하네스 변경을 직접 말함) | inferred(우리 판단·제안) | none(하네스 관련 언급 없음)",
  "source_url": "이 사실이 나온 공식 출처 URL — 반드시 위에서 준 출처 URL을 쓴다"
}

규칙: 원문에 없는 사실을 만들지 않는다. 오래전부터 있던 설명을 새 출시처럼 과장하지 않는다.
같은 변경을 여러 항목으로 쪼개지 않되, 서로 다른 모델의 변경은 모델별로 따로 낸다.
바뀐 내용이 실제로 없으면(예: 문구만 재배치) 빈 배열 []만 출력한다.
