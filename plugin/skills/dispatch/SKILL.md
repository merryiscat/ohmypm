# dispatch — 스펙과 검토는 밖에서, 구현은 여기서

**구현은 main이 한다.** 2026-09-18 개정으로 코디네이터 자리와 워커 워크트리를 걷어냈다.
2026-09-19 개정으로 **설계의 상한을 걷어냈다** — pl은 코드를 읽고 되물으며, 왕복 횟수에 제한이 없다.
절차의 규칙은 `docs/protocol.md`가 소유하고, 이 스킬은 **명령줄과 문구만** 소유한다.

## 0. 차선 판정과 예상 시간 (10초)

| 차선 | 기준 | 이 스킬에서 |
|---|---|---|
| **S 즉시** | 되돌리기 쉽다(revert 한 번) · 운영 영향 없음 · 요청이 곧 완료 기준 | **직접** 한다. 커밋 메시지에 요청 원문 한 줄. 끝 |
| **M 표준** | 여러 파일 · 판단 조금 · 되돌릴 수 있음 | 2절 → 3절 → 4절(10초 게이트) → 5절 구현 → 6절 |
| **L 중대** | 운영 · 되돌리기 어려움 · 구조 변경 · 미지 | 같은 절차, 게이트는 스펙 전체 |

**기본은 S다.** 사용자가 "가볍게"·"제대로"라고 하면 그게 이긴다.
판정과 **예상 시간을 한 줄로 말하고 시작한다**: "M으로 갑니다 — 파일 셋, 되돌릴 수 있음. 15분쯤 걸립니다."
반복 운영 업무는 첫 회 차선대로, 이후는 **스펙 파일을 재사용해** 바로 구현한다.

**요청을 받을 때 명백히 빠진 것이 하나 있으면 그 자리에서 묻는다.** 답은 **사용자 말 그대로** 요청 원문에 덧붙인다 —
원문이 길어지는 것은 괜찮고, 배경·해석을 덧붙이는 것은 안 된다(2026-09-18 T-003에서 배경 한 줄이 설계를 통째로 끌고 왔다).

## 1. 자리 찾기

```
orca terminal list --worktree path:<pl 워크트리 절대경로> --json
```
**`name:pl`을 쓰지 않는다** — 작업 구조가 깔린 프로젝트가 여럿이면 선택자가 모호해진다(2026-09-19 실측).
`pl` 워크트리에서 **Codex 프로세스 = pl(스펙), Claude 프로세스 = pl2(검토)**. 제목이 아니라 화면으로 판별한다.
없으면 kickoff-workspaces 3절대로 연다.

**모델은 `docs/roles.md`의 벤더별 우선순위로 맨 앞부터 부른다**(protocol 10절). 터미널이
`out of usage credits` 류로 답하면 **같은 벤더의 다음 모델**로 `/model`을 보내고 다시 지시한다.
벤더를 넘어가지 않는다 — 한 벤더가 통째로 막히면 그 자리는 멈추고 사용자에게 알린다.
**실제로 응답한 모델을 `--model`로 로그에 적는다.** `roles.md`도 터미널 배너도 설정값이지 가용성의 증거가 아니다(2026-09-19 오독 실측).

## 2. pl에 스펙 지시

**긴 지시를 `--text`로 보내지 않는다.** 큰따옴표가 들어가면 인자가 쪼개진다(2026-09-19 실측).
지시서를 파일로 쓰고 경로만 보낸다 — `pipeline-log.py send`가 그 일을 하면서 원문을 로그에 남긴다.

1. 지시서를 `<pl 워크트리>/docs/_ask/T-NNN.md`에 쓴다. 담을 것:
   - **요청 원문 블록** — 사용자가 한 말 그대로. 요약·해석·유사 태스크 언급 금지
   - 차선(M/L), 스펙 파일 경로, 템플릿 형식, 완료 기준 개수 상한
   - **범위 밖** — 원문에 있으나 이번 판에서 다루지 않을 것을 사유와 함께
   - **읽을 범위** — 대상 코드·문서의 경로. 저장소 전체를 훑게 두지 않는다(로그상 병목이 여기다)
2. 보낸다:
```
python <플러그인>/skills/kickoff-workspaces/scripts/pipeline-log.py send \
  --task T-NNN --to pl --terminal <pl handle> --file docs/_ask/T-NNN.md \
  --stage "스펙 v1 지시" --model <그 자리가 실제로 응답한 모델>
```
3. 끝났는지는 **파일 생성 + 화면에서 작업 표시가 사라짐**으로 판단한다. 기다릴 때는 **실패도 함께 본다** —
   파일만 기다리는 대기는 에이전트가 오류로 멈춰도 영원히 기다린다(2026-09-19 실측).
4. 받은 산출물을 로그에 남긴다:
```
pipeline-log.py recv --task T-NNN --from pl --file docs/tasks/T-NNN-<slug>.md --stage "스펙 v1"
```

**pl이 되물으면** 그 자리에서 사용자에게 올린다 — 재확인 주기도, 쌓아 둘 큐도 두지 않는다.
답을 받으면 `docs/_ask/T-NNN-answer.md`에 **사용자 말 그대로** 적어 다시 `send`한다. 왕복 횟수에 상한은 없다.

## 3. pl2에 검토 지시

지시서 `docs/_ask/T-NNN-review.md`에 담을 것: 대상 스펙 경로와 판(vN), 차선, protocol 4절 규칙
(0번 요청 대조 먼저 / 지적마다 실패 시나리오 / 재작성 금지 / M은 차단만 10줄 이내).
**주는 것은 요청 원문·스펙·산출물뿐이다** — main의 세션 로그나 추론은 주지 않는다(독립성).

```
pipeline-log.py send --task T-NNN --to pl2 --terminal <pl2 handle> --file docs/_ask/T-NNN-review.md --stage "검토 지시" --model <실제 응답 모델>
pipeline-log.py recv --task T-NNN --from pl2 --file docs/reviews/T-NNN.review-v1.md --stage "검토서 v1" --model <실제 응답 모델>
```

검토서가 나오면 **pl2를 비운다**(PowerShell에서 — Git Bash는 `/clear`를 경로로 바꾼다):
```
orca terminal send --terminal <pl2 handle> --text "/clear" --enter --json
```

차단이 있으면 pl에 v2 지시(`docs/_ask/T-NNN-v2.md`). **사용자 결정이 필요한 지적은 v2 지시 전에 물어**
결정을 지시서에 그대로 싣는다. 나머지 지적에는 main의 판단과 근거를 붙여 "다르게 보면 기각하고 근거를 써라"고 한다.
차단 기각이 있으면 토론하지 말고 사용자에게 올린다.

**내용이 달라진 판은 다시 검토해도 된다**(protocol 4절). 금지선은 *같은 내용을 다시 보는 것* 하나뿐이다.

## 4. 게이트 (사용자)

스펙·검토서를 pl 브랜치에 커밋 → main에 ff 머지 → 푸시(원격이 있으면).
- **M은 10초**: 용도 한 줄과 완료 기준 목록만 그대로 보이고 "이대로 갑니다" 한 줄. **생략하지 않는다**
- **L은 스펙 전체**: 목표·범위 밖·산출물을 두 문장으로 요약해 승인을 받는다

## 5. 구현 (main, 여기서 직접)

승인된 스펙의 완료 기준을 만족시킨다. 스펙 밖은 고치지 않는다 — 필요해지면 멈추고 묻는다.
오래 걸릴 명령은 백그라운드로 돌리고 진행 로그를 남긴다. 사용자가 화면으로 진행을 보므로 중간 보고는 짧게.
끝나면 완료 기준을 항목별로 `통과/실패 + 확인한 방법`으로 적는다.

## 6. 산출물 검토 (pl2) → 토큰 수집 → 커밋

지시서 `docs/_ask/T-NNN-verify.md`: 커밋 sha, protocol 4절 산출물 검토, 스펙의 완료 기준마다 통과/실패를
`검증` 표에 적을 것, 0번 요청 대조 먼저, **고치지 않는다**. 실패면 사유를 받아 **main이 고치고** 다시 받는다(2회까지).

전부 통과면 **토큰을 걷고 나서** 비운다 — 순서를 바꾸면 숫자가 사라진다:
```
orca terminal send --terminal <pl handle> --text "/status" --enter --json     # Token usage 줄을 읽는다
pipeline-log.py usage --task T-NNN --role pl --raw "<그 줄 그대로>"
orca terminal send --terminal <pl handle> --text "/clear" --enter --json
pipeline-log.py report --task T-NNN                                            # 집계를 사용자에게 보인다
```

마지막으로 **실제 걸린 시간을 사용자에게 말하고** `docs/benchmark.md`에 한 줄 적는다
(요청 일치·검토 차단·산출물 실패·시간·사람 개입·**토큰 실측**).

## 7. 동시 요청

- **main은 한 자리다.** main2를 만들지 않는다. 구현이 main에서 도므로 요청은 직렬로 처리한다
- 대기 중인 요청은 `docs/status.md`에 "대기: <원문>"으로 적어 두고 순서대로
- pl은 직렬: 한 번에 스펙 하나. 다음 태스크 지시는 앞 태스크를 비운 뒤에
- 태스크 상태의 단일 출처는 스펙 파일의 `상태:` 줄이다

## 하지 않는 것

- M·L 요청을 스펙 없이 바로 구현하기("금방 하니까"). S는 직접 하는 게 맞다 — 차선을 먼저 말하고 한다
- **긴 지시를 `--text`로 보내기** — 지시서 파일 + 경로 한 줄. `send`가 그렇게 한다
- **`pipeline-log.py send`를 건너뛰고 `orca terminal send`로 직접 보내기** — 로그가 비면 그 바퀴는 측정 실패다
- `/status`를 걷기 전에 `/clear` 하기 — 숫자가 사라진다
- pl2에게 **같은 내용**을 두 번 검토시키기, main의 세션 로그·추론을 주기
- **워커 워크트리 띄우기, `orca orchestration` 쓰기** — 2026-09-18 걷어냈다
- 질문을 쌓아 두고 나중에 올리기 — 즉시 올린다. 09-18 병목의 원인은 아무도 보지 않는 대기였다
- 목록으로 터미널 닫기 — 내가 만든 핸들만 닫는다. 사용자 세션 건드리기
- 일하는 중인 터미널("esc to interrupt / ctrl+b")에 메시지 보내기
- Git Bash에서 `/clear` 보내기 — MSYS가 경로로 바꾼다. PowerShell이나 `MSYS_NO_PATHCONV=1`
