# dispatch — 스펙과 검토는 밖에서, 구현은 여기서

**구현은 main이 한다.** 2026-09-18 개정으로 코디네이터 자리와 워커 워크트리를 걷어냈다 — 근거가 없었고
이벤트 소비자가 둘이 되며 병목을 만들었다. 남은 것은 **스펙 한 장과 교차 검토 한 번**이다.
절차의 규칙은 `docs/protocol.md`가 소유하고, 이 스킬은 **명령줄과 문구만** 소유한다.

## 0. 차선 판정과 예상 시간 (10초)

| 차선 | 기준 | 이 스킬에서 |
|---|---|---|
| **S 즉시** | 되돌리기 쉽다(revert 한 번) · 운영 영향 없음 · 요청이 곧 완료 기준 | **직접** 한다. 커밋 메시지에 요청 원문 한 줄. 끝 |
| **M 표준** | 여러 파일 · 판단 조금 · 되돌릴 수 있음 | 2절 → 3절 → 4절(10초 게이트) → 5절 구현 → 6절 |
| **L 중대** | 운영 · 되돌리기 어려움 · 구조 변경 · 미지 | 같은 절차, 게이트는 스펙 전체 |

**기본은 S다.** 사용자가 "가볍게"·"제대로"라고 하면 그게 이긴다.
판정과 **예상 시간을 한 줄로 말하고 시작한다**: "M으로 갑니다 — 파일 셋, 되돌릴 수 있음. 15분쯤 걸립니다."
반복 운영 업무는 첫 회 차선대로, 이후는 **스펙 파일을 재사용해 pl 없이** 바로 구현한다(pl 턴 0).

## 1. 자리 찾기

```
orca terminal list --worktree name:pl --json
```
`pl` 워크트리에서 **Codex 프로세스 = pl(스펙), Claude 프로세스 = pl2(검토)**. 제목이 아니라 명령으로 판별한다.
없으면 kickoff-workspaces 3절대로 연다. `roles.md` 맨 위 모드 줄이 `fable-out`이면 pl2는 오퍼스다.

## 2. pl에 스펙 지시 (Codex 턴 1)

한 줄. **요청 원문을 그대로** 싣고 무엇을 만들라는지만 덧붙인다. **배경·해석·유사 태스크 언급을 덧붙이지 않는다** —
2026-09-18 T-003에서 "T-002 테스트셋을 재사용하라"를 배경으로 붙였다가 T-002의 A/B 평가 설계가 통째로 따라왔다.
이전 산출물을 꼭 가리켜야 하면 **따를 것과 따르지 말 것을 같이** 적는다.
```
orca terminal send --terminal <pl> --enter --wait-submit 10 --json --text \
 "사용자 요청(원문 그대로): <원문>. 차선 <M|L>. 이걸 docs/tasks/T-NNN-<slug>.md 스펙 하나로 써라(_template.md 형식. 맨 위 '요청 원문' 칸에 이 문장을 그대로 옮기고, 완료 기준은 거기서만 뽑아라. 기준 하나는 한 줄. M이면 기준 ≤ 5·전체 30줄, L이면 ≤ 8·한 장). 셸은 docs 읽기·쓰기에만, src·코드 실행 금지. 다 쓰면 한 줄 보고하고 멈춰라."
```
번호 NNN은 `docs/tasks/`의 다음 번호. **보내기 전에 pl이 비어 있는지** 확인한다 — 이전 문맥이 남아 있으면 `/clear`부터(종량).
끝났는지는 **파일 생성 + 화면에서 "esc to interrupt"가 사라짐**으로 판단(폴링 5초).

## 3. pl2에 스펙 검토 지시

```
orca terminal send --terminal <pl2> --enter --wait-submit 10 --json --text \
 "pl이 docs/tasks/T-NNN-<slug>.md v1을 완성했다(차선 <M|L>). protocol 4절대로 docs/reviews/T-NNN.review-v1.md를 한 번만 쓰고 결론을 한 줄로 보고하라. 0번 요청 대조를 먼저 적어라 — 스펙의 '요청 원문'과 완료 기준이 같은 것을 말하나. 원문에 없는 산출물·열·행·판정이 기준에 있으면 차단이다. 지적마다 실패 시나리오를 붙이고, 못 쓰면 그 지적은 버려라. M이면 그 뒤 차단 항목만 10줄 이내, 차단 없으면 '대조: 일치 / 지적 없음' 한 줄. 다른 파일은 건드리지 않는다."
```
검토서가 나오면 **pl2를 비운다**(PowerShell에서 — Git Bash는 `/clear`를 경로로 바꾼다):
```
orca terminal send --terminal <pl2> --text "/clear" --enter --json
```
차단이 있으면 pl에 v2 지시(Codex 턴 2). 사용자 결정이 필요한 지적이 섞여 있으면 **v2 지시 전에** 물어 결정을 지시문에 싣는다:
```
... --text "pl2 검토서 docs/reviews/T-NNN.review-v1.md가 나왔다. [사용자 결정: …] 지적마다 '검토 반영' 표에 수용/기각(근거)을 적고 본문을 v2로 고쳐라(상태: 검토 반영 v2). 이 턴 하나로 끝낸다. 끝나면 '차단 기각 있음/없음' 한 줄만."
```
차단 기각이 있으면 토론하지 말고 사용자에게 올린다.

## 4. 게이트 (사용자)

스펙·검토서를 pl 브랜치에 커밋 → main에 ff 머지 → 푸시(원격이 있으면).
- **M은 10초**: 용도 한 줄과 완료 기준 목록만 그대로 보이고 "이대로 갑니다" 한 줄. **생략하지 않는다** — 사용자가 착수 전에 스펙을 보는 유일한 지점이다
- **L은 스펙 전체**: 목표·범위 밖·산출물을 두 문장으로 요약해 승인을 받는다

## 5. 구현 (main, 여기서 직접)

승인된 스펙의 완료 기준을 만족시킨다. 스펙 밖은 고치지 않는다 — 필요해지면 멈추고 묻는다.
오래 걸릴 명령은 백그라운드로 돌리고 진행 로그를 남긴다. 사용자가 화면으로 진행을 보므로 중간 보고는 짧게.
끝나면 완료 기준을 항목별로 `통과/실패 + 확인한 방법`으로 적는다.

## 6. 산출물 검토 (pl2) → 커밋

```
orca terminal send --terminal <pl2> --enter --wait-submit 10 --json --text \
 "T-NNN 구현이 끝났다(커밋 <sha>). protocol 4절 산출물 검토: 스펙의 완료 기준마다 통과/실패를 판정해 docs/tasks/T-NNN-<slug>.md '검증' 표에 적어라(M이면 기준별 한 줄, 재조회는 차단 기준만). 0번 요청 대조를 먼저 — 산출물이 '요청 원문'이 말한 것인가. 고치지 않는다. 끝나면 한 문단 보고."
```
전부 통과면 커밋·푸시. 실패면 사유를 받아 **main이 고치고** 같은 검토를 한 번 더 받는다(2회까지).
스펙 자체를 고쳐야 하면 그때만 pl을 켠다.

마지막으로 **실제 걸린 시간을 사용자에게 말하고** `docs/benchmark.md`에 한 줄 적는다(요청 일치·검토 차단·산출물 실패·시간·사람 개입).
그리고 pl·pl2를 비운다.

## 7. 동시 요청

- **main은 한 자리다.** main2를 만들지 않는다. 구현이 main에서 도므로 요청은 직렬로 처리한다
- 대기 중인 요청은 `docs/status.md`에 "대기: <원문>"으로 적어 두고 순서대로
- pl은 직렬: 한 번에 스펙 하나. 다음 v1 지시는 앞 태스크의 v2 보고(+`/clear`) 뒤에
- 태스크 상태의 단일 출처는 스펙 파일의 `상태:` 줄이다

## 하지 않는 것

- M·L 요청을 스펙 없이 바로 구현하기("금방 하니까"). S는 직접 하는 게 맞다 — 차선을 먼저 말하고 한다
- pl에 조사·질문·대기 시키기, pl에 세 번째 메시지 보내기
- pl2에 같은 대상을 두 번 검토시키기, pl2에게 main의 세션 로그·추론을 주기(독립성이 깨진다)
- **워커 워크트리 띄우기, `orca orchestration` 쓰기** — 2026-09-18 걷어냈다
- 목록으로 터미널 닫기 — 내가 만든 핸들만 닫는다. 사용자 세션 건드리기
- 일하는 중인 터미널("esc to interrupt / ctrl+b")에 메시지 보내기
- Git Bash에서 `/clear` 보내기 — MSYS가 경로로 바꾼다. PowerShell이나 `MSYS_NO_PATHCONV=1`
