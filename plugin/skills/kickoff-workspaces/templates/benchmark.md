# 작업 구조 비교 기록 — 로컬 전용

1.0이 강한 단일 모델보다 도움이 되는지는 반복 비교로 판단한다. 구현 테스트 통과는 모델 품질 우위의 증거가 아니다.

## 비교 방법

동일한 원문·시작 커밋·도구·완료 기준을 두 조건에 제공한다. 한쪽 결과를 다른 쪽에 보여 주지 않는다.
가능하면 순서를 바꾸어 여러 대표 작업을 반복하고, 모델·예산·사용자 개입 차이를 함께 기록한다.
단순 수정은 main 직접 처리, 복잡한 설계·구현은 main/pl/work 대상으로 구분한다.

| 날짜 | 작업 ID | 조건(단일/1.0) | 모델·버전 | 요구 누락 | 결함 | 사용자 수정 횟수 | 시간 | 비용·사용량 | 검증 근거 |
|---|---|---|---|---|---|---|---|---|---|

비용·사용량을 얻지 못하면 미측정으로 쓴다. 리뷰 지적 수를 품질 점수로 대신하지 않는다.
몇 번의 성공으로 일반화하지 않는다. 사용자와 품질 이득 및 추가 시간·비용을 확인한 뒤 선택한 프로젝트로 확대한다.

## 판단 기록

실측 전. 관찰한 이득·실패·적용할 작업 유형·사용자 결정을 여기에 기록한다.
1.0.0은 사용자 요청으로 새 작업 구조를 도입한 버전이며, 비교 실험 합격을 뜻하지 않는다.

이 파일은 git 미추적이다. 공개되는 스펙·검증 표에는 개인 경로·다른 프로젝트의 비공개 정보를 옮기지 않는다.
