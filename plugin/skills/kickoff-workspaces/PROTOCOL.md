# ohmyPM 2.0 작업 프로토콜

프로젝트와 작업 환경을 분리한다. 실행기·절차·템플릿은 외부 불변 패키지,
역할별 모델·원문·승인·질문·증거는 Git 공통 디렉터리 ohmypm/에 보존한다.
설치·갱신·해제는 프로젝트 추적 파일, index, HEAD, 지침, 훅을 수정하지 않는다.
프로젝트 고유 규칙·빌드 설정·제품 설계는 프로젝트 자산이다.

## 접수와 설계
main은 읽기 조사 후 수정 전에 처리 경로·근거·범위를 표시하고 route에 기록한다.
새 화면·사용자 기능/흐름·데이터 계약·권한·연동·비가역 변경은 pl로 연결한다.
명확하고 작고 가역적인 수정만 direct다. 파일 개수나 예상 시간으로 판정하지 않는다.
범위가 커지면 수정 전에 재분류한다. 정보가 부족하면 조사하거나 pl에서 사용자와 논의한다.
pl은 합의한 최고 성능 모델로 설계·완료 기준(최대 8개)·검증·소유 경로·하네스를 정한다.
사용자가 특정 revision 구현을 요청해야 work를 준비한다. main은 승인·pl 판정을 대체하지 않는다.

## 실행과 검증
main은 runtime/config/route/spec/manifest를 고정하고 실제 사용자 결정을 기록한다.
독립성이 입증된 work만 최대 두 개 병렬이다. work는 승인 범위에서 구현하고 workflow exec로
검증해 제출한다. pl은 코드와 실제 동작을 확인하고 commit/base/revision/digest에 묶인 판정을 남긴다.
기준이나 통합 후보가 바뀌면 재검증한다. main은 깨끗한 등록 체크아웃에 검증 결과만 로컬 머지한다.
푸시·배포는 별도다. 대역 테스트와 실제 모델/Orca 증거를 구분한다.

## 세션과 복구
main/pl은 role-connect와 context 수락으로 연결한다. 임의 세션이 자동 연결되었다고 간주하지 않는다.
pl 종료 확인 또는 최초 미등록이면 main이 새 세션을 준비하고 영속 자료에서 이어가게 한다.
실제 모델 프로세스의 생성 식별자·종료 코드를 기록한다. 셸 생존이나 tui-idle만으로 판단하지 않는다.
응답 지연·통신 실패는 불명 상태다. 불명 상태에서 중복 생성하거나 기존 세션을 종료하지 않는다.
질문은 outbox에 보존하고 전송·수락·완료를 구분한다. 과거 generation/revision 답변은 적용하지 않는다.
종료만으로 기존 승인·유효 판정을 무효화하지 않는다. work는 승인 범위를 계속 수행할 수 있으나
필요한 pl 판정 전에는 머지하지 않는다. 새 pl 위치와 이어받은 revision을 사용자에게 안내한다.
Codex pl은 사용자 지정에 따라 --dangerously-bypass-approvals-and-sandbox로 시작한다.
실행 정책도 프로필과 작업 계약에 기록하며 approval=default를 명시하면 기본 CLI 정책을 사용한다.

## 업데이트와 전환
업데이트는 미래 작업에만 적용한다. 진행 작업은 정확한 패키지 해시를 계속 사용한다.
패키지 누락·변조·schema 불일치는 실행을 거부한다. 참조 중 패키지는 자동 제거하지 않는다.
1.0 상태와 설치본은 자동 전환하지 않는다. 기존 작업은 보존된 1.0 실행기로 마무리한다.
전환은 plan, 검토된 digest의 apply, 검증 순서다. 사용자 수정·불명확한 소유권·훅은 보존한다.
추적 설치본 정리는 별도 일회 변경이며 자동 stage/commit/push하지 않는다. 다른 프로젝트 전환도 별도다.
disable은 새 작업을 막고 증거·활성 작업을 보존한다. 상태와 외부 패키지는 별도 백업한다.
