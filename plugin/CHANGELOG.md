# ohmypm 플러그인 변경 내역

프로젝트 설치 버전은 `docs/protocol.md` 첫 줄, 플러그인 버전은 `.claude-plugin/plugin.json`에 있다.

## 1.0.0 — 2026-09-21

사용자 요청으로 main 접수·운영 / pl 설계·품질 / 작업별 work 구현 구조로 이전한다.
이번 1.0.0 구현에 한해 기존 pl 문서 전용·검증 금지 제한의 예외를 사용자가 승인했다.

- pl은 사용자와 여러 차례 설계하고 코드·동작을 검증한다. 상시 pl2·pl3와 두 번만 호출하는 제한을 폐지한다.
- Python 표준 라이브러리 실행 도구 추가: 버전별 계약·승인, Orca 환경 준비·실행, 기준별 증거, 커밋에 연결된 판정, 순차 로컬 머지·회수.
- 독립 작업만 프로젝트 전체 최대 두 개 병렬. 의존성·설정·포트·데이터를 작업별로 준비한다.
- 원문·결정·증거·실행 상태는 Git 공통 디렉터리에 보존한다. 중복 호출·중단은 실제 상태를 대조하고, 불명확한 에이전트 실행·메시지를 자동 반복하지 않는다.
- 설치기 `ws_upgrade.py` 추가. 0.x 이전은 `--migrate-v1`, 관리 파일 백업, 기존 작업·터미널 보존. 전체 배포는 별도 요청으로 제한한다.
- 프로젝트 소유 파일 손질: `docs/workflow.json`에 역할별 모델 선택을 옮기고, `orca.yaml`에서 새 work의 의존성 공유를 제거한다. 기존 폴더·링크는 삭제하지 않는다.
- 기존 PM 점검·대시보드·보고는 유지한다. 원격 푸시·배포·PM 화면 통합은 이번 범위 밖이다.

1.0.0은 새 작업 구조를 도입하는 버전이다. 0.x의 "비교 합격 두 번 뒤 1.0" 규칙은 이번 사용자 결정으로 대체한다.
모델 품질 우위가 검증되었다는 뜻은 아니다. 단일 모델과의 반복 비교 뒤 사용자가 확대 여부를 정한다.

## 버전·이전 원칙

행동과 계약의 호환성을 기준으로 PATCH/MINOR/MAJOR를 구분한다. 기존 작업에는 새 계약을 소급 적용하지 않는다.
관리 파일은 설치기로 갱신하고, 프로젝트 소유 설정은 보존·검토한다. 진행 중 세션을 자동 초기화하지 않는다.
되돌릴 때는 코드와 프로젝트 복사본을 함께 복원하며 Git 공통 디렉터리의 백업·작업 증거를 보존한다.
아래 0.x 항목의 역할·버전 규칙은 당시 이력이며 현행 절차는 `docs/protocol.md`다.
